## 各項目の詳細（本書の記述と再現方法の補足）

> **用語ミニ解説（よく出てくる基本語）**
> - **プロシージャル**: 画像ファイルに頼らず、数式やノードの組み合わせで模様・質感をリアルタイム生成する方式。
> - **PBR（物理ベースレンダリング）**: 金属度（Metallic）や粗さ（Roughness）など物理法則に近い数値でリアルな質感を再現する考え方。
> - **ベイク（Bake）**: 複雑なシェーダー計算やハイポリの凹凸情報を、軽い2Dテクスチャ画像へ事前に焼き込む処理。
> - **リトポロジー（リトポ）**: スカルプトで作った高密度メッシュの表面に沿って、アニメーション・UV展開しやすい整ったポリゴンを張り直す作業。
> - **スキニング**: メッシュの頂点がどのボーン（骨）にどれだけ追従するか（ウェイト）を割り当てる作業。

### `BL-001` 3D空間の基本構造・操作モード・モディファイア・コレクション
- **出典**: 『プロフェッショナル Blender』Part 1 Ch.1–4（本書 p.22–71 / PDF p.22–71）

#### 本書の記述（要約）
Blender の 3D 空間は「シーン」配下に「オブジェクト（位置・回転・スケール等の器）」と「オブジェクトデータ（メッシュ・ライト・カメラ等の実体）」が分離して成り立っている。用途に応じてオブジェクト／編集／スカルプト／ポーズ／ウェイトペイントの各モードを切り替え、非破壊の「モディファイア」は上からの適用順序が結果に影響する。複数オブジェクトの整理には「コレクション（1オブジェクトが複数所属可能）」を活用する。

#### Gemini による再現方法の補足（現行版での変更点・他ツール移植を含む）
- **Blender**: 現行版（4.2〜4.5 LTS / 5.0系）でもオブジェクト／データの分離構造・モディファイアスタック・コレクションは不変。**現行版では** 3.x〜4.0 にあった法線「自動スムーズ」チェックが廃止され、モディファイアの **`Smooth by Angle`**（または右クリック「角度でスムーズシェード」）で制御する点に注意。
- **After Effects**: シーン＝コンポジション、オブジェクト＝レイヤー、非破壊モディファイア適用順＝エフェクトスタックの適用順、コレクション＝プリコンポーズやラベルカラー管理に相当。
- **DaVinci Resolve**: Fusion ページの `Merge3D` がシーン階層、`Transform3D` がオブジェクト空間、ノードの直列接続順がモディファイア適用順に相当する。

### `BL-002` データブロック参照切替・未使用削除・外部データパック
- **出典**: 『プロフェッショナル Blender』Part 1 Ch.5（本書 p.72–79 / PDF p.72–79）

#### 本書の記述（要約）
メッシュ・マテリアル・カメラ・ライト・画像などの実体はすべて「データブロック」として管理され、プロパティのプルダウンから参照先を差し替えるだけで同じ形状や質感を複数オブジェクトで共有・切替できる。どこからも参照されていない未使用データブロックは次回のファイル保存・再開時に自動削除されるため、残したい場合は保護設定が必要。別環境への持ち出し時は「相対パス化」や「外部データのパック（`.blend` 内へ同梱）／パック解除」を使う。

#### Gemini による再現方法の補足（現行版での変更点・他ツール移植を含む）
- **Blender**: 未使用データの保護はデータブロック右横の盾アイコン（**フェイクユーザー `F`**）をオンにする。**現行版では** アセットブラウザ連携も強化され、再利用したいマテリアルやメッシュは右クリック「アセットとしてマーク」で別ファイルから参照可能。
- **After Effects**: プロジェクトパネルのフッテージ参照差し替え（`Alt+ドラッグ`）や、`ファイル > 依存関係 > ファイルを収集`（外部データ同梱）・「未使用フッテージを削除」に相当。
- **DaVinci Resolve**: メディアプールのマスター素材共有や、`ファイル > プロジェクトアーカイブを書き出し（.dra）` による外部メディア一括同梱に相当。

### `BL-015` テクスチャスキャッタリング（2D Voronoi・ランダム回転・多重合成）
- **出典**: 『プロフェッショナル Blender』Part 2 Ch.12（本書 p.206–222 / PDF p.210–226）

- **Blender**: **現行版（4.2 以降）でも** `-b`（`--background`）・`-P`（`--python`）・`--`（スクリプト専用引数の区切り）の CLI 体系は完全維持されており、外部通信を遮断する `--offline-mode` 等も利用可能。
- **After Effects**: `aerender.exe` コマンドラインレンダラー＋事前 `.jsx` 書き換えによるバッチ自動書き出しに相当。
- **DaVinci Resolve**: Resolve Studio のヘッドレス/外部 Python API 経由による `AddRenderJob()`・`StartRendering()` 自動書き出しに相当。

### `BL-028` `subprocess.run()` 外部連携と複数3Dモデル一括 `.blend` 変換
- **出典**: 『プロフェッショナル Blender』Part 5 Ch.3–5（本書 p.436–464 / PDF p.444–472）

#### 本書の記述（要約）
外部の通常 Python プログラムから標準ライブラリ `subprocess.run()`（コマンド配列渡し）で Blender をサブプロセスとして呼び出し、`--` 以降のコマンドライン引数で対象ファイルパスを渡すパイプライン構成。これにより、フォルダ内の複数 3D モデル（Wavefront `.obj` 等）を順次自動インポートし、`.blend` ファイルへ一括変換・保存するバッチ処理を構築できる。

#### Gemini による再現方法の補足（現行版での変更点・他ツール移植を含む）
- **Blender**: **現行版（4.0 以降）では** 旧 Python 製 OBJ インポータ `bpy.ops.import_scene.obj` は廃止され、高速な C++ ネイティブ版 **`bpy.ops.wm.obj_import(filepath=...)`** / **`bpy.ops.wm.obj_export(...)`** を使用する点に注意。
- **After Effects**: Python 等から `subprocess.run()` で `AfterFX.exe -r script.jsx` や `aerender` を呼び出し、複数素材を一括プロジェクト化・書き出しする構成に相当。
- **DaVinci Resolve**: 外部 Python スクリプトから Resolve API へ接続し、複数プロジェクトや大量クリップの一括変換・タイムライン生成を回す構成に相当。

### `BL-029` Addon の導入・配置構造と基本アーキテクチャ（Operator / Panel）
- **出典**: 『プロフェッショナル Blender』Part 6 Ch.1–2（本書 p.466–489 / PDF p.474–497）

#### 本書の記述（要約）
GUI 作業中に繰り返し行う定型操作（ブーリアン穴あけ設定等）をワンボタン化したり、標準にない高度な編集や外部サーバー連携まで追加できるのが Addon である。自作 Addon は Blender 本体の標準フォルダではなくユーザーデータ側のアドオンフォルダへ配置するとバージョンアップ時の引き継ぎに有利。単一 `.py` または `__init__.py` を起点に、テンプレート `addon_add_object.py` に倣って `Operator`（実行処理）・`Panel`（`bpy.types.Panel` 継承＋`draw()` 内の `UILayout`）・`register()` / `unregister()` を組む。

#### Gemini による再現方法の補足（現行版での変更点・他ツール移植を含む）
- **Blender**: 本書 Part 6 Ch.1（本書 p.467 / PDF p.475）では旧来 UI の「アドオン > インストール」と `bl_info` 形式を解説しているが、**現行版（4.2 以降）では** ローカル ZIP 導入は右上メニュー `∨ > ディスクからインストール（Install from Disk）` へ移動し、公式エクステンション配布では `bl_info` に代わる **`blender_manifest.toml`** 形式が標準となっている（既存の `bl_info` 形式レガシーアドオンも引き続き動作）。
- **After Effects**: `ScriptUI Panels` フォルダへ配置するドッキング可能 `.jsx` パネルや CEP / UXP 拡張パネル開発に相当。
- **DaVinci Resolve**: `Fusion/Scripts` や `UI Manager`（`UIDispatcher`）で自作ウィンドウ・ボタン付きツールを作る構成に相当。

### `BL-030` ソリッドモデルのロボットスキニング自動化 Addon（Robot Skinner）
- **出典**: 『プロフェッショナル Blender』Part 6 Ch.3（本書 p.490–512 / PDF p.498–520）

#### 本書の記述（要約）
パーツ数の多いロボット等のソリッド（剛体）モデルでは、モデリング中は「ボーン相対ペアレント」で仮組みしておき、ゲームエンジン出力前に全頂点へぴったり **100%** のウェイトを割り当てるスキニングが必要になる（本書 p.491 / PDF p.499）。これを自動化する自作 Addon（`Robot Skinner`）では、アクティブなアーマチュアの子メッシュを一括取得し、①二重変形を防ぐためボーン相対ペアレントを解除（アーマチュアへ変更）、②既存ウェイトを整理して該当ボーン名の頂点グループへ `add(..., weight=1.0, type='REPLACE')` でウェイト設定、③`アーマチュアモディファイア` を自動追加・関連付けする一連の処理をパネル＆オペレーターとしてモジュール分割実装する。

#### Gemini による再現方法の補足（現行版での変更点・他ツール移植を含む）
- **Blender**: **現行版でも** 頂点グループ操作（`obj.vertex_groups.new` / `vg.add(..., 1.0, 'REPLACE')`）と `obj.modifiers.new(..., type='ARMATURE')` の API は安定してそのまま動作する。
- **After Effects**: 剛体パーツ（ロボやUI部品）の関節制御は、ウェイト変形なしで親レイヤー／ヌルへ直接親子付けする方式が標準（ソフトボディ変形のみパペットピンを使用）。
- **DaVinci Resolve**: Fusion 3D の剛体パーツは `Transform3D` 階層での親子付け（リジッドリグ）で完結し、スキニング済み FBX を外部（Blender 等）から受け取る運用になる。

## 1. 背景（なぜ「映像から断定できない項目」の決まりが必要か）

Track C 第1優先の実証試験により、**完成映像（レンダリング結果・動画）だけを見た AI の推定精度には、明確な「よく当たる領域」と「系統的にズレる領域（視覚的限界）」の境界がある**ことが数値で確認されました。

- **映像から高精度に推定でき、レシピの主軸として信頼できる領域**:
  - カメラ焦点距離帯（広角／標準／望遠: **3/3 = 100%**、平均絶対誤差 5.83mm）
  - 明確な浅い被写界深度の F 値（`classroom`: 正解 f/2.08 vs 推定 f/2.0）
  - コード映像のモーション方式分類（**4/4 = 100%**）および主要イージング・数式関数の種類（**13/13 = 100%**）
  - 代表配色（HEX コード: `#141414`, `#10b981` 等）
- **映像だけでは系統的にズレるため、断定してはいけない領域**:
  1. **ライトの総数**（10灯→4灯、9灯→4灯と複数灯リグで半分以下に過小推定）
  2. **HDRI / 発光メッシュ単独か、実ライト（SUN 等）併用かの判別**（0灯の `lone_monk` を 1灯 SUN と誤認）
  3. **コンポジットノード使用有無・ノード構成**（106ノードの `classroom`・14ノードの `lone_monk` とも「未使用」と誤認、一致 **1/3**）
  4. **被写界深度（DOF）の境界**（`f/11.2` の深い DOF は DOF 無効と区別不可、逆に滑らかな床面／デノイザを浅い DOF と誤認、一致 **1/3**）
  5. **View Transform / トーンマップ名**（`Standard` vs `Filmic` / `AgX` の厳密な判別、一致 **2/3**）
  6. **コード／エフェクトの厳密な数値係数**（`waitFor` 秒数、`noiseScale` 1/250、パーティクル数 `n=1400`、ストローク不透明度 `6/255`、角周波数係数など）

これらをレシピ本文に「ライト4灯」「コンポジット未使用」「`noiseScale=0.01`」と断定記載すると、手本としての再現信頼性を損ないます。そこで、**「視覚的に断定できない項目は `non_visual_unknowns` 欄へ明示的に退避し、再現レシピ本文ではレンジ表記・参考初期値（例示）として扱う」**規約を定義します。

## 2. `non_visual_unknowns` 記載規約（案）

### 規約 1：断定禁止カテゴリ（必ず `non_visual_unknowns` へ記載する6領域）
完成映像のみから `craft_recipes` を生成する場合（`.blend` / `.aep` / ソースコード / 公式 BTS 等の一次資料がない場合）、以下の 6 領域は**単一の実測事実として断定してはならず**、該当する項目を必ず `non_visual_unknowns` 配列に明記する。

| カテゴリ | 断定禁止の例（NG） | レシピ本文での許容表記（OK） | `non_visual_unknowns` への標準記載例 |
|---|---|---|---|
| **① ライト総数・HDRI 判別** | 「AREA 4灯構成」「SUNライト1灯を使用」 | 「主光は強い指向性光（HDRI太陽またはSUNライト想定）＋複数の補助面光（参考初期値: 3〜8灯で要調整）」 | `ライトの正確な総数・出力値、および指向性主光がHDRI/発光メッシュ単独かSUNライト併用かの判別` |
| **② コンポジット有無・内部ノード順** | 「コンポジットノード未使用の生レンダー」「Glare→Lens Distortion の2ノード」 | 「明確なグレアは弱いが、微細な露出・歪み・色補正コンポジットが含まれる可能性あり（再現時は参考チェーンとして提示）」 | `視覚変化の小さいコンポジットノード（微弱なExposure/Glare/Lens Distortion/Curves等）の有無と正確なノード数・接続順` |
| **③ ピントの深さ（DOF 境界）** | 「DOF無効（パンフォーカス）」「f/2.8 で撮影」 | 明確な前景／背景ボケがある場合のみ「浅いDOF（f/2.0〜2.8相当の参考値）」。全域シャープまたは微ボケ時は「深いDOF（f/8〜16相当）またはDOF無効」と併記 | `DOF設定のON/OFF厳密判別（深いF値とDOF無効の区別、およびデノイザ/テクスチャ平滑化との切り分け）と正確なセンサー幅・焦点距離` |
| **④ カラーマネジメント／LUT 名** | 「Filmic Medium Contrast 確定」「露出 0.0」 | 「ハイライトロールオフが穏やかなフィルミック系トーン（再現時は Filmic / AgX の Medium Contrast 付近を起点に調整）」 | `View Transform（Standard / Filmic / AgX）およびLookプリセット名、Exposureとライト強度/コンポジット露出の相殺関係` |
| **⑤ コード／モーションの厳密係数** | 「`waitFor(0.5)`」「`noise(i/100)`」「`alpha=10`」 | 「`easeInOutCubic` 系の加減速（参考初期値: 0.3〜0.6秒）」「2D Perlinノイズ場による低不透明度線の蓄積（参考初期値: alpha 2〜5%）」 | `各トゥイーン・待機（waitFor）の厳密秒数、ノイズ周波数係数（noiseScale）・シード値・線本数・正確なアルファ値・角周波数係数` |
| **⑥ 実機・ソフト名（画面外情報）** | 「Maya + Arnold で制作」「ARRI Alexa + 35mm 単焦点」 | 「手元再現は Blender Cycles（広角 24〜28mm 相当）を推奨」※元ソフト推定ではなく手元再現の推奨ツールとして記述 | `元制作で使用された実カメラ機種・レンズ銘柄・実制作ソフト/レンダラー名・レンダリングサンプル数` |

### 規約 2：「観察事実（推定可）」と「再現用参考値（調整前提）」の明示分離
- `craft_recipes` 内のパラメータ数値は、次の 2 種類を区別する：
  - **`observed_or_measured`**: ffmpeg 実測値（尺・カット間隔・LUFS・ピクセル代表 HEX）や画面内で直接視認できる幾何構造・動きの種別。
  - **`recreation_starting_point`**: 再現作業を始めるための初期パラメータ（ライト灯数、F値、イージング尺、ノイズスケール等）。これらは「元データの正解値」ではなく「再現用たたき台」である旨を前提とし、元データの真値としては `non_visual_unknowns` に残す。

### 規約 3：定型コピー防止（作品ごとの具体化要件）
- `non_visual_unknowns` は全作品に同一の定型文をコピペしてはならない。
- その作品の表現種別（3DCG 静止画／モーショングラフィックス／コード映像／実写・VFX 等）に応じて、**実際にその作品で視覚的曖昧さが生じている 2〜5 項目に絞って具体的に記載**する（例：2D コード映像に「HDRI と SUN ライトの区別」を書かない）。

## 3. JSON スキーマ記載例（3DCG 作品 / コード映像）

```json
{
  "non_visual_unknowns": [
    "中庭からの強い指向性光がHDRI/Sky単独かSUNライト併用か、および室内補助ライトの正確な総数",
    "全域シャープな描写がDOF無効によるものか、広角×深いF値（f/8〜f/11等）によるものかの区別",
    "視覚変化の小さいコンポジットノード（Exposure補正・微弱なGlare/Lens Distortion等）の有無とノード構成",
    "View Transform（Standard / Filmic / AgX）および正確なExposure/Gamma値"
  ]
}
```

```json
{
  "non_visual_unknowns": [
    "Perlinノイズの空間周波数係数（noiseScale）・seed値・オクターブ設定",
    "同時描画される点/線分の正確な本数、1フレームあたりの移動ステップ量、および厳密なストローク不透明度",
    "実装フレームワーク（p5.js / Processing / Canvas 2D / GLSL等）の特定"
  ]
}
```

# 較正テスト実施プロトコル（事前固定版・v2）

本プロトコルは、較正テストの実行前にすべての条件・データ分割・ブラインド化検証・スロー区間適用ルール・合格基準を固定し、結果を見た後の基準変更（後出し調整）を禁止するために策定する。

---

## 1. テストの位置づけ（試しの較正・本番DB非書込）
- 本テストは **「試しの較正（Dry-run）」** として実行し、**本番TiDB / SQLite への書き込みは一切行わない**。
- 結果は採点方式（静止画方式 vs 動画方式）の精度比較および改善目安として扱い、そのまま本番ランクの付け直しには使用しない。

---

## 2. 動画読み込みの技術的前提（1fpsの限界）と共通実測値・スロー区間ルール
1. **1秒1コマ（約1fps）の限界の明記**：
   - Antigravity の `read_file` でローカル `.mp4` を読み込む際、映像は**およそ1fps（1秒1フレーム）**で抽出・供給される（音声トラックは連続波形として全編聴取可能）。
   - したがって、通常速度（1x）の `.mp4` だけでは **1秒未満の高速カットやフレーム単位の細かい動きは見落とす限界がある**。「動画方式＝動きを完全に把握できる」とは絶対に表記しない。
2. **両方式への共通実測値提供（公平性の担保）**：
   - 静止画方式・動画方式の**双方に同一フォーマットで `ffmpeg scdet` の実測カット数・平均カット間隔・カット密度分布・音声ラウドネス（LUFS）を添えて**渡す。
3. **高密度区間スロー確認ルール（事前固定・恣意選択禁止）**：
   - 細かい動き・高速カットが採点に影響する区間を実質 2〜4fps で確認するため、以下の**100%決定的な機械ルール**でスロー区間を自動抽出する（人間やAIが結果を見て区間を恣意的に選ばない）：
     - **適用条件（いずれか該当で自動発動）**：
       1. `ffmpeg scdet` で10秒スライディング窓の最大カット密度が **`cuts_per_10s >= 6`**（平均カット間隔 `< 1.67秒`）
       2. ジャンルが **`モーション`**（カット数が少なくても連続モーショングラフィックスの細部確認が必要なため、動画中央の10秒区間を対象）
     - **倍率ルール**：
       - `6 <= max_cuts_per_10s < 12`（またはモーション）：最大カット密度10秒区間を切り出し、**2倍スロー（`setpts=2.0*PTS`、出力20秒・実質約2fps、無音 `-an`）**を生成。
       - `max_cuts_per_10s >= 12`（超高速カット・平均0.83秒未満）：最大カット密度5秒区間を切り出し、**4倍スロー（`setpts=4.0*PTS`、出力20秒・実質約4fps、無音 `-an`）**を生成。
     - **静止画方式との公平比較**：
       - スロー区間が発動した同一動画・同一区間について、静止画方式でも**同じ密集区間を切り出した高密度4×4コンタクトシート（16フレーム追加）**を供給し、時間分解能の偏りを防ぐ。
     - **記録義務**：全動画について `slowmo_applied`, `slowmo_factor` (`2x`/`4x`), `slowmo_window_sec` (`[start, end]`) をログに記録する。
4. **大容量・長尺動画（15MB超・事前チェック該当17本）の軽量再エンコードルール**：
   - `ffmpeg scdet` およびスロー区間切り出し・コンタクトシート生成は、**必ず元のダウンロード済み動画から実行する**（時間分解能・カット検出精度を落とさない）。
   - 動画方式で `read_file` へ渡す全編MP4が **15MB超** の場合（最大：`8pOOxOo7YYo` 756秒・40.15MB 等、全17本）は、一律で `ffmpeg -vf "scale=-2:360" -c:v libx264 -crf 30 -preset fast -c:a aac -b:a 64k` により15MB未満へ軽量再エンコードして供給する。
   - 再エンコード後も上限超過・読み込みエラーとなる場合は時間均等2分割して同一サブエージェントへ連続供給し、全動画について `transcoded`, `input_size_bytes`, `split_parts` をログに記録する。

## 3. 厳格なブラインド化とリーク機械監査ルール
1. **採点者の完全分離（新規サブエージェント限定）**：
   - 採点は1動画・1実行ごとに**必ず新しい独立サブエージェント**が行う。
   - 親エージェント（すでに `5URefVYaJrA` / `tdQCMuaJUQk` / `7rP-633ApUI` を事前確認で視聴済み）は**一切採点しない**。
2. **隔離作業フォルダ・ID単体ファイル名**：
   - 採点対象ファイルは `analysis/golden_benchmark.json` 等が存在するリポジトリとは別の隔離作業ディレクトリ（`<ArtifactDir>/scratch/blind_eval/<mode>/<video_id>/`）に、**動画IDのみの名前**（`<video_id>.mp4`、スロー時は `<video_id>_slow.mp4`、静止画方式は `<video_id>_sheet_01.jpg` 等）で配置する。
   - 採点プロンプトには **作品タイトル・チャンネル名・既存DBランク・受賞歴・AI分析本文を一切渡さない**（渡すのは隔離ファイルパスと共通の `ffmpeg scdet`/LUFS 実測数値のみ）。
3. **採点後の会話ログ機械監査（違反は即無効）**：
   - 採点完了後、各サブエージェントの `transcript.jsonl` を機械検証し、ツール呼び出しが**割り当てられた対象ファイルへの `read_file` のみ**であることを確認する。
   - `golden_benchmark.json` / `benchmark_split.json` / DB / リポジトリ内スクリプト等、割り当て以外のファイルや外部検索へアクセスした採点は**自動無効**とする。
4. **採点後の既知・受賞表示チェック（感度分析）**：
   - 点数確定後（同じ応答の末尾または直後）に、採点者へ以下の3問を必ず回答させる：
     1. `knows_work`：この作品（ブランド・アーティスト・作品名）を知っていたか
     2. `knows_award_history`：この作品の受賞歴を知っていたか
     3. `award_badge_visible_in_video`：動画の画面内や音声内に賞の表記・トロフィー等が表示されていたか
   - 集計レポートでは、**①全件を含む結果**と、**②上記いずれかに該当した作品を除外した結果**の両方を必ず併記する。

## 4. 事前固定する合格基準・Holdout 1回限りルール・コミット固定
1. **合格基準（結果を見て変更しない）**：
   - 合否は **確認用セット（Holdout）の点推定値** で判定し、**ブートストラップ95%信頼区間（$B=2,000$回）を必ず併記**する。

| 指標 | 対象 | 合格基準（固定・点推定値） | 算出仕様 |
|---|---|---|---|
| **順位相関（Spearman $\rho$）** | Holdout `craft_benchmark`（14本） | **$\rho \ge 0.85$** | 平均順位法（同点補正付き）＋95%信頼区間、Kendall's $\tau_b$ 併記 |
| **誤差（Band-distance MAE）** | Holdout `craft_benchmark`（14本） | **$\text{MAE} \le 4.0$点** | 正解ランク帯 $[L_i, U_i]$ 内なら `0`、帯域外なら最も近い端までの点差の平均 |
| **順位の正解率（Pairwise / ROC-AUC）** | Holdout `A-`以上 `craft_benchmark`（14本） vs Holdout `non_award_baseline`（20本） | **$\ge 0.85$** | 受賞・選出作のAI点数 ＞ 非受賞商用作品のAI点数となる組み合わせ割合＋95%信頼区間 |

2. **確認用（Holdout）の1回限り原則**：
   - **確認用セットは1回だけ実行する**。不合格だった場合、同じ確認用セットを使ってプロンプトを再調整・再判定してはならない。
3. **確認用実行前の完全凍結（Freeze Commit）**：
   - 調整用（Dev）での調整が完了し確認用（Holdout）を実行する直前に、**採点プロンプト・ルーブリック・使用モデル名・アンサンブル条件（2+1方式）・スロー適用スクリプトをすべて git コミットして凍結**し、確認用レポートにその **凍結コミットハッシュ（SHA）** を明記する。

## 2. Phase 2 で検証する主張の再定義

### 2.1 基本方針（人手ラベル・自社AIラベル・動画中身選別の全面禁止）
- **正解ラベル付けに人間の主観的品質判断は一切使わない**（ユーザーの手作業ラベリングを行わない）。
- **正解ラベル付けに Gemini / Antigravity も一切使わない**（循環定義・自己整合バイアスの完全排除）。
- **確認用（New Holdout）の収集・事前確認時に、AI が動画の中身（映像・音声・コンタクトシート）を見て選別・判定することも厳格に禁止**する（完全非接触収集）。
- すべての正解ラベルは、**客観的な外部事実（賞の一次資料・制作元／クレジット事実・投稿者自身が明記したメタ情報やツール由来の事実）のみ** から決定論的な規則で機械的に確定する。

|---|---|---|

## 3. 事実ベースの正解ラベル規則と完全非接触収集ルール（採点前に凍結）

### 3.1 共通原則（「迷ったら入れない」・排他・非接触収集・根拠記録）
1. **規則で一意に決まらない作品は収集対象外**とする（「見た目がプロっぽい／安っぽい」等の主観判断による採否を一切禁止）。
2. **`R-PRO-*` と `R-LOW-*` の重複該当は収集対象外（厳格な排他規則）**：
   - 例：企業公式チャンネルが公開した「ノーカット説明会録画」「PowerPoint 書き出し紹介動画」、制作クレジット付きだが「無編集固定カメラ記録」である動画など、**`R-PRO-*` と `R-LOW-*` の両方に当てはまる動画はいずれの区分にも入れず、必ず収集対象外とする**。
3. **完全非接触の収集原則（確認用リーケージ防止）**：
   - 候補収集・採否決定は、**タイトル・概要欄・タグ・チャンネル情報・公式クレジット・一次出典ページのテキストメタ情報、および `yt-dlp` / `ffprobe` / 後述のローカル OCR の機械出力のみ** で行う。
   - **Gemini / Antigravity（および一切の VLM）が動画の映像・音声・コンタクトシートの中身を見て、出来の良し悪しや雰囲気で作品を選ぶ・除外することは厳格に禁止する**。
4. **画面内受賞ロゴ・テロップの事前検出（ローカル `ffmpeg` + ローカル OCR 方式）**：
   - `award_badge_visible_in_video_precheck` の確認に **Gemini / Antigravity へ動画や画像を見せることは厳格に禁止**する。
   - 代わりに、以下の **完全ローカル・決定論的パイプライン** を全候補動画に機械適用する（使用する OCR エンジンとバージョンは収集開始前コミットで固定）：
     - **コマ切出し（`ffmpeg`）**：冒頭 15 秒および末尾 20 秒を **`1.0 fps`**（映画祭ローレル・エンドカード受賞表記が集中する区間）、中間本編を **`0.2 fps`（5秒間隔）** で `scale=-2:720` PNG に切り出す。
     - **ローカル OCR**：ローカル実行の **`Tesseract OCR`（`eng+jpn`）**（または収集前コミットで固定した単一ローカル OCR エンジン）を全切出しフレームに適用する。
     - **事前固定キーワード正規表現（大文字小文字無視）**：
       `cannes|lions|d&ad|pencil|ciclope|aicp|british arrows|acc\s*tokyo|ukmva|sxsw|annecy|siggraph|ars electronica|adfest|vimeo staff pick|staff pick|shortlist|grand prix|gold lion|silver lion|bronze lion|palme d'or|academy award|oscar|emmy|webby|clio|new york festivals|motion awards|space shower|メディア芸術祭|新千歳|受賞|最優秀|グランプリ|金賞|銀賞|銅賞|入賞|オフィシャルセレクション|official selection|award winner`
     - **判定閾値（事前固定・安全側除外）**：OCR トークン信頼度 **`conf >= 60`（0–100スケール）** の抽出テキストに対し、上記正規表現が **1フレーム以上ヒットした場合** に `award_badge_ocr_hit: true` とし、**AI に中身を見せることなく機械的に収集対象外（自動除外）** とする（安全側のため偽陽性による除外を許容する）。
     - **完全監査ログと除外本数報告（必須）**：検査した全候補について、**ヒットしたキーワード・該当フレーム時刻（秒）・OCR 抽出テキスト・信頼度（`confidence`）・検査フレーム数・エンジン名とバージョン** を構造化ログ（`ocr_precheck_log.jsonl`）にすべて保存し、収集完了時に **自動除外した総本数および全除外作品ID・ヒット明細を必ず報告** する（誤検出で除外された作品を後から外部監査できるようにするため）。
5. **作品ごとの根拠記録スキーマ（収集前凍結・git コミット必須）**：
   収集した全作品について以下を JSON に記録して凍結する：
   - `video_id` / `url` / `platform` / `genre` / `published_year`
   - `stratum`: `tier2_award` / `non_tier2_pro` / `non_tier2_low`
   - `label_rule_id`: 適用した規則ID（例：`R-T2-03`、`R-PRO-01`、`R-LOW-02`）
   - `evidence_url`: 一次出典・公式チャンネル・制作会社クレジットページ・当該動画ページ等の根拠URL
   - `evidence_excerpt`: 判定根拠となった原文抜粋（受賞部門名、制作会社クレジット表記、投稿者の「初心者」明記文言など）
   - `view_count_at_collection` / `collected_at`: 収集時点の再生数・日時
   - `award_badge_ocr_hit`: ローカル OCR 事前チェック結果（`false` のみ収録、検出エンジン・バージョン・フレーム数を併記）
6. **重複・実取得チェック（全区分共通）**：
   - Phase 1 全83本および Dev 追加分との重複（動画ID・作品名・同一作品別URL）を完全排除。
   - `yt-dlp`＋`ffprobe` で実取得可否・再生時間・解像度・音声有無を事前検証。

## 5. 事前固定の合格基準と主判定方式の固定

### 5.1 主判定方式の事前固定（多重比較の禁止）
- New Holdout（75本）では比較・分析のため、同一ラン上で **①ハイブリッド方式、②静止画単独、③動画単独** の3方式のスコアをすべて算出・記録する。
- ただし、**合否を判定する「主判定方式」は事前に「①静止画基本＋動画併用のハイブリッド方式」の1つに固定**する。
- ②静止画単独・③動画単独の結果は **参考値（アブレーション・コスト比較）** として併記するのみであり、確認用の結果を見て主判定方式を差し替えることは厳格に禁止する。

### 5.2 可変本数（$N_{\text{T2}} \in \{20, 23, 24, 25\}$・$N_{\text{PRO}} \in \{20, 25\}$）の合格本数換算式（事前固定）
企業映像が下限適用または未検証扱い（4ジャンル一致 $N_{\text{T2}} = 20$ vs $N_{\text{PRO}} = 20$）となり本数 $N$ が変動した場合の解釈ブレを防ぐため、割合基準の必要達成本数・許容誤り上限本数を以下の式で事前に完全固定する：
- **下限基準（$\ge p$）の必要達成本数**：$\text{必要本数} = \lceil p \times N \rceil$
- **上限基準（$\le q$）の許容誤り上限本数**：$\text{許容上限本数} = \lfloor q \times N \rfloor$

### 5.3 主判定（Primary：`Tier 2` vs 同一ジャンル構成の `プロ商業` のみ）の合格基準（固定案）
対象：**主判定方式（ハイブリッド方式）** による New Holdout（1回限り実行）の **点推定値**（ブートストラップ 95% CI $B=2,000$回および 3群×スコア帯クロス表を必ず併記）。

| # | 指標（主判定対象：**`Tier 2` vs 同一ジャンル構成の `プロ商業`**） | 合格基準（固定案） | 本数別の exact 合格ライン（事前固定式） | 設計意図 |
|---|---|---|---|---|
| **P-1** | **ROC-AUC（Pairwise：`Tier 2` vs `プロ商業`）** | **$\ge 0.90$** | 連続値 $\ge 0.9000$<br>（※$N_{\text{T2}} \in \{23,24,25\}$ 時は $N_{\text{PRO}}=25$ 対比；**企業未検証 $N_{\text{T2}}=20$ 時は4ジャンル一致 $N_{\text{PRO}}=20$ 対比を主判定**とし、全プロ商業25本対比は参考値として併記） | 簡単な低品質やジャンル不一致の偏りを混ぜず、同一ジャンル群のプロ商業から受賞水準を見抜く純粋な識別力。 |

| **P-3** | **特異度（`プロ商業` 特異度：`score < T_award`）** | **$\ge 84.0\%$** | $\lceil 0.84 \times N_{\text{PRO}} \rceil$<br>（5ジャンル25本→**21本以上**［誤陽性4本以内］／**企業未検証・4ジャンル一致20本→17本以上**［誤陽性3本以内］；25本対比21/25は参考併記） | 負例から低品質25本および未検証ジャンルを外した純粋な同一ジャンル・プロ商業のみでも推奨精度を高水準に保つため 84% に設定（Phase 1 使用済み非受賞43本の実測は動画 39/43＝90.7%・静止画 37/43＝86.0%、うち `>=63` 商業帯約29本に対する実質特異度は静止画約79%・動画約86%）。 |
| **P-4** | **重大誤り上限 A（`Tier 2` を低品質帯 `< T_low` に置く誤り）** | **$0.0\%$** | $\lfloor 0.00 \times N_{\text{T2}} \rfloor =$ **0本**（20〜25本共通） | 受賞水準を低品質帯に落とす致命的誤りを厳格禁止（Phase 1 参考値：両方式とも 0/27＝0.0%）。 |

対象：**主判定方式（ハイブリッド方式）**。**透かし規則 `R-LOW-04` を「①含む全低品質（$N_{\text{LOW}}=25$）」と「②除く低品質（`R-LOW-01`〜`03` のみ、$N \ge 20$）」の両方で算出・報告**する。

| # | 指標（補助判定：`明らかな低品質` の分離） | 合格基準（固定案） | 本数換算式・併記ルール |
|---|---|---|---|
| **S-1** | **重大誤り上限 B（`明らかな低品質` を `>= T_award` と誤る率）** | **$\le 4.0\%$** | $\lfloor 0.04 \times N_{\text{LOW}} \rfloor$（25本→**1本以内**）。`R-LOW-04` 除外サブセット（$N \in [20,24]$ は $\lfloor 0.04 \times N \rfloor = 0$本目安）の実数・率も必ず併記。 |

### 5.5 参考値および最終機械判定ルール（事前固定）
- **参考値として必ず併記するもの（主合否には不使用）**：
  1. `Tier 2` vs `それ以外（プロ商業＋明らかな低品質 計50本）` の ROC-AUC・感度・特異度。
  2. 静止画単独・動画単独の P-1〜P-4・S-1〜S-3 およびトークン実測比較。
  3. 既知除外サブセット（`knows_work` または `knows_award_history` が true の作品を除外）での P-1〜P-4・S-1〜S-3。
- **最終機械判定ルール**：
  - **採用（GO）**：主判定 **P-1〜P-4 すべて達成**、かつ 補助判定 **S-1〜S-3（全低品質）すべて達成**、かつ **`R-LOW-04` 除外サブセットで透かし依存による急落がないこと（S-2 $\ge 0.90$ かつ S-3 Pairwise $\ge 0.75$）**。
  - **保留（低品質分離の再設計）**：主判定 P-1〜P-4 は達成したが、補助判定 S-1〜S-3 のいずれかが未達（または `R-LOW-04` 除外サブセットで上記急落条件に該当）。
  - **不採用（NO-GO）**：主判定 P-1〜P-4 のいずれかが未達（本番適用不可）。

### 5.6 Dev 境界点数 $(T_{\text{award}}, T_{\text{low}})$ の事前固定決定規則および Holdout ロック（採点開始前登録）
Dev プール（Phase 1 残存 Dev＋追加 Dev 31本）を用いた境界探索において、結果を見た後の恣意的な境界選択（後出し調整）を完全に排除するため、以下の機械選択規則を **Dev 採点開始前** に固定する（結果を見てから規則を変更しない）。

1. **探索グリッド（1点刻み）**
   - $T_{\text{award}} \in \{75, 76, \dots, 84\}$、$T_{\text{low}} \in \{58, 59, \dots, 68\}$（ただし $T_{\text{low}} \le T_{\text{award}} - 5$）。
   - 各組について、ハイブリッド方式（6.2節）のスコアに対し `evaluatePhase2Scores` を実行し、GO／HOLD／NO-GO および Youden's $J = \text{P-2（感度）} + \text{P-3（特異度）} - 1$ を算出する。
2. **一意決定ルール（タイブレーク規則）**
   - `decision === "GO"` を満たす候補の中から、**Youden's $J$ が最大** となる候補群（`bestRows`）を抽出する。
   - 候補が1組のみならその組を採用する。
   - **GO かつ Youden's $J$ 最大の候補が複数ある場合**、表の並び順に依存せず以下の規則で機械的に決定する：
     1. **$T_{\text{award}}$ の決定**：`bestRows` に含まれる $T_{\text{award}}$ の連続区間（1点刻みの連続範囲）のうち最長区間を取り、その **中央値（偶数個なら高い方：`run[Math.floor(run.length / 2)]`）** を選ぶ（最長区間が同長で複数ある場合は区間内最大 `P-1 AUC` が高い方、さらに同値なら点数の高い区間）。
     2. **$T_{\text{low}}$ の決定**：決定した $T_{\text{award}}$ に属する `bestRows` の $T_{\text{low}}$ について同様に最長連続区間を取り、その **中央値（偶数個なら高い方）** を選ぶ。
3. **合格範囲の幅の併記義務**
   - 境界決定の報告には、採用値 $(T_{\text{award}}, T_{\text{low}})$ だけでなく、**GO となる全候補の合格範囲の幅（$T_{\text{award}}$ 何点〜何点、$T_{\text{low}}$ 何点〜何点が GO か）** を必ず併記する。
   - なお、Phase 1 残存 Dev のみ（$N_{\text{PRO}}=9$、使用済みデータ）の事前シミュレーション値は楽観的な参考値として扱い、本規則の適用対象は追加 Dev 31本を含む統合 Dev プールとする。
4. **Holdout 実行前のロック検証（`scripts/prepare-phase2-run.mjs`）**
   - `--split holdout` の実行には `--confirm-frozen-holdout` と `--frozen-config <path>` が必須であり、さらに以下を機械検証して 1 つでも満たさない場合は `BLOCKED` として即停止する：
     - `--frozen-config` で指定されたファイルがリポジトリ内にあり、**git `HEAD` にコミット済みで作業ツリーとバイト完全一致**すること（未コミット変更の禁止）。
     - 設定ファイル内の `frozen_commit` が 7〜40 桁の 16 進コミットハッシュであり、**`git cat-file -t <frozen_commit>` が `commit` として実在**すること。

## 6. 方式設計：静止画基本＋動画併用ハイブリッドの決定ルール

### 6.1 Phase 1 の実測根拠
- **コスト・精度バランス**：Holdout 実測で静止画方式は、初回読込後生入力トークンが動画方式の **約 1/5.6（`3,404` vs `19,200`）**、effective でも **約 1/2.4（`11,189` vs `26,925`）** でありながら、MAE（`3.00` vs `3.31`）・Pairwise（`0.9654` vs `0.9635`）は同等以上だった。
- **静止画方式が弱かった領域（動画併用が必要な具体的ケース）**：
  1. **音楽同期・ビート主導の MV**：音ハメ・緩急・音響統合を聴取できないため静止画が一貫して 6.5〜8.0点過小評価した（`ebzEEEdjHj0` 動画93 vs 静止画85、`49367868` 93.5 vs 86、`5zj3aHgLFQE` 91 vs 84.5、`153159513` 91.5 vs 85）。
  2. **純モーション作品**：イージングや連続モーフィングの心地よさが静止コマでは伝わりにくい（`1032202784` 動画92.5 vs 静止画88.5）。
  3. **紙芝居・静的スライド・固定カメラ長回し**：絵柄が整った紙芝居（`GvkbAp9YZCo` 動画57 vs 静止画66.5）やインタビュー主体（`CWhNI_x9W6c` 動画69 vs 静止画78.5）では、静止画方式が「動きの乏しさ・整音の粗さ」を見落として高めに採点する傾向があった。
- **動画方式の留意点**：音声・楽曲・冒頭クレジット経由で S帯の **12/12本（100%）** が既知申告となった（静止画は 9/12＝75%）。

### 6.2 ハイブリッド運用ルール（完全決定論的・後出し裁量禁止）
すべての動画に対して、まず共通前処理（`ffprobe` + `ffmpeg scdet=threshold=10` + `ebur128` 統合ラウドネス + コンタクトシート生成）を実行し、以下の **2段階の機械ルール** で方式を自動決定する。

```text
[全作品] ──(事前機械判定：ルール H1)──┬── 該当 ──▶ 【動画方式（2+1）】で最終判定
                                       │            （MV / モーション / 高速カット作品）
                                       └── 非該当 ─▶ 【静止画方式（2+1）】で一次採点
                                                      │
                                        (境界・静的動画トリガー：ルール H2)
                                                      ├── 該当 ──▶ 【動画方式（2+1）】へ自動エスカレーションし動画スコアで確定
                                                      └── 非該当 ─▶ 【静止画方式スコア】で確定
```

1. **ルール H1（事前動画ルーティング：音ハメ・モーション・高速カット優先）**
   以下のいずれかを満たす作品は、最初から **動画方式**（高密度区間スロー併用・2+1アンサンブル）で採点する：
   - **H1-a**：ジャンルが **`MV`**
   - **H1-b**：ジャンルが **`モーション`**
   - **H1-c**：ジャンル・音量を問わず、**`max_cuts_per_10s >= 12`**（10秒間のシーン切替が12回以上の高速カット・高密度編集作品）
     - ※v1 にあった `integrated_lufs >= -18.0` の音量条件は **撤廃** した（無音または低音圧の高速カット／モンタージュ／タイポグラフィ作品も静止画の固定コマ抽出では情報欠落が大きいため、音量に関係なく動画方式へ回す必要があるため）。
2. **ルール H2（境界帯・静的動画エスカレーション：静止画→動画の精査）**
   H1 非該当の作品（CM・3DCG/アニメ・企業映像の大半）はまず **静止画方式**（2+1アンサンブル）で採点し、以下のいずれかに該当した場合のみ **動画方式** を追加実行して動画スコアで最終確定する：
   - **H2-a（境界付近の曖昧ゾーン）**：静止画スコアが、Dev で事前固定した境界の前後 ±3.0点以内（**`[T_award - 3.0, T_award + 3.0]`** または **`[T_low - 3.0, T_low + 3.0]`**）に入った場合。
   - **H2-b（紙芝居・静的スライド・固定カメラ長回し疑い）**：**`duration_sec >= 60.0` かつ `avg_cut_interval_sec >= 15.0`**（または `total_cuts <= 2`）で静止画スコアが **`>= T_low`** の場合（動きの乏しさや実測音声不備を動画方式で確認し、スライド・紙芝居の過大評価を防ぐ）。
   - **H2-c（極端な低音圧・無音疑い）**：**`integrated_lufs <= -28.0` または `integrated_lufs === null`** で静止画スコアが **`>= T_low`** の場合（無音放置・整音不備の確認）。
3. **モデル固定・監査要件の継続**
   - 採点モデル名は引き続き明示的モデル名（例：`gemini-4-neon-high`）で事前固定し、`audit-blind-transcript.mjs --strict --expected-model` による 100% 一致・完全隔離検証を維持する。
   - 本番運用想定（CM・企業映像の比率が高い本番DB構成）では、全件動画方式比で **入力トークン約 45〜65% 削減** を見込む（5ジャンル均等の New Holdout では約 35〜45% 削減見込み）。

## 7. Phase 1 診断メモ（構造的知見・永続記録）

Phase 1（Dev 37本＋Holdout 33本＝有効70本）のブラインド実測から得られた、今後の評価基準・データ設計で繰り返し参照すべき構造的知見を以下に記録する。

### 7.1 「賞の格」と「映像クラフトの出来」が一致しない代表例
1. **`X0hyTmlsBUI`（`ORIGAMI` / デジタルハリウッド学生3DCG短編）**
   - 客観ラベル：Academy Awards 短編アニメ Shortlist → `S-`（`90–92`）
   - AI実測：動画 **81.5点** `(81, 82)` / 静止画 **80.5点** `(82, 79)`（帯域距離 `8.5` / `9.5`）
   - 要因：和紙質感や構成の詩情は評価された一方、終盤明部のCGライティングの平坦さ・造形の粗さ・紙擦れ等のフォーリーSE不在を一貫して減点。**学生制作・映画祭ショートリストの総合評価（着想・物語性・将来性）と、商業最上位クラフト基準とのギャップ**が露呈した。
2. **`iIL_CB_YjFk`（講談社ブランドムービー `Inspire Impossible Stories`）**
   - 客観ラベル：基準セット上は `A+`（`86–89`）
   - AI実測：動画 **95.0点** `(96, 94)` / 静止画 **92.0点** `(90, 94)`（帯域距離 `6.0` / `3.0`）
   - 要因：実写から紙・書籍で組んだ超精密ミニチュア都市への展開、紙の煙・擬音タイヤ・4倍スローでも破綻しない工芸的作り込みを両方式とも国際最上位（`S` / `S-`）と評価。**出品した賞の格と純粋な映像クラフト到達度は必ずしも1対1対応しない**。
3. **`vpyeQeTDGFA`（Honda "Paper"）・`5wEjV2ekSwE`（Honda "Hands"）vs `vRBVWCs1KW4`（"Blinkity Blank", 1955）**
   - 客観ラベル：前2作は `S-`（`90–92`）、後者はカンヌ短編パルムドールで `S+`（`97–100`）
   - AI実測：Honda 2作が動画 **96.5 / 95.0**・静止画 **93.5 / 93.0** に対し、`Blinkity Blank` は動画 **93.5**・静止画 **92.5**。
   - 要因：1955年実験アニメーションの歴史的・映画史的価値と、現代の高密度商業クラフトを単一の100点スケール上で厳密に順位付けすること自体に構造的限界がある。
4. **BOVA（宣伝会議）内での企画系と実写クラフト系の逆転**
   - **`wXD33Jx25oI`**（BOVA 2026 **ゴールド**：ギャンブル依存症・レトロゲーム風、`A` `82–85`）→ 動画 **75.0点** / 静止画 **73.5点**（`B+`）。発想・構成の鋭さは高評価だが、簡易ベクター作画と反復構成がクラフト面で減点された。
   - **`FSqTqdjf2YQ`**（BOVA 2025 **シルバー**：東亞合成アロンアルフア、`A-` `78–81`）→ 動画 **84.5点** / 静止画 **86.0点**（`A`/`A+`）。映画的撮影・照明・抑制的グレーディング・演技演出が高く評価され、下位賞が上位賞を約10点上回った。
   - 要因：BOVA は公式基準（3つの“鋭さ”）上、課題発見・企画アイデアの比重が高く、映像クラフト単体の序列とは構造的にズレる。

### 7.2 有名作品の「既知申告（`knows_work` / `knows_award_history`）」と画面内ロゴ
- **S帯の既知率（Phase 1 全70本合算）**：
  - 動画方式：S帯 **12 / 12本（100.0%）** が既知または受賞表示あり（`craft_benchmark` 全体でも **18 / 27本＝66.7%**、うち `knows_work = 16/27`）。
  - 静止画方式：S帯 **9 / 12本（75.0%）**、`craft_benchmark` 全体で **12 / 27本（44.4%）**。
- **原因**：動画方式では楽曲・ボーカル・ナレーション・冒頭/末尾の監督/ブランドクレジットがそのまま手掛かりとなり、著名国際受賞作はパスやタイトルを完全ブラインド化しても作品自体を特定されやすい。
- **画面内アワードロゴの実例**：`V6XHz7tqGVM` では本編 05:04〜05:08 に `ADFEST 2016` ロゴが表示され、動画方式 2/2回が `award_badge_visible_in_video: true` を検出（静止画方式は 0/2回）。一方、投稿タイトルに「WINNER」を含んでいた `5wEjV2ekSwE` は本編画面内に受賞表記がなく、全4回とも `award_badge_visible_in_video: false` だった。
- **Phase 2 への反映**：第3.1〜3.2節のとおり、再生数上限（YouTube `< 500,000` / Vimeo `< 100,000`）および公開年（`2022–2026年`）を数値で固定し、画面内ロゴの有無は **ローカル `ffmpeg` + ローカル OCR** で AI 非接触のまま事前自動除外する。

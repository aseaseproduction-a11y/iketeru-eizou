ユーザーの「好きな映像」の系譜は以下の通りであり、一次資料から抽出された imoutoid の制作原則と高い親和性を持つ：

| ユーザーの好む映像例 | 表現上の核 | 適用する制作原則との対応 |

| **Norman McLaren『Blinkity Blank』** | フィルムへの直接彫刻による1フレーム単位の残像・ちらつき・知覚実験と、音・打撃との精密な同期 | 原則 (d) 知覚の仕組みの活用／原則 (b) 手作業限界を超える単位の設計 |

## 2. 一次資料の4原則と映像領域への読み替え

### 原則 (a)：実験は、ポップの中でこそ意味がある
- **一次出典（本人記事のみ・`sc-av-studio/docs/references/imoutoid-production-philosophy.md` より）**：
  - 『今日のグリッチノイズ』（2007-10-29）：「こうやってただランダムに鳴らすなら兎も角、これをポップな音楽に取り込もうとすると途端に難しくなる。」「それと、簡単にGlitchな音が作れる方法を発見したものの、多用しすぎるのもなんだかな。」「サンプル破壊系では、サンプル音の選択は非常に重要ですね。どうせ壊すからなんでも入れりゃ良いってもんじゃないや。」「半自動生成ツールは、常にその両方の橋渡しをしなければいけません。」
  - 『グリッチ脳で曲が出来た』（2007-11-11）：「グリッチとか欠片もないよ。ひたすらポップだ。」
  - 『だれかとえろいことしたいな』（2009-01-28）：環境音を1024分音符単位で4小節シーケンスした実験を「曲にあんまり馴染まなかった。ちとやりすぎた。」としてボツにしている。
- **映像領域への読み替え（【推測】・設計指針）**：
  - グリッチ・視覚的破壊・アルゴリズム的逸脱などの実験表現は、単独で全編にばらまくのではなく、**明快な構成・リズム・キャッチーな視覚フック（ポップの土台）の上に「見せ場」として配置する**ことで効力を発揮する。
  - 加工・破壊する元の素材（輪郭・コントラスト・リズムの明快さ）の選定にも妥協しない。
  - **【設計上の仮の目安】**：※以下は imoutoid 本人の発言ではなく、本プロジェクトの映像構成設計における仮の目安である。基本構成の **約80% を安定・反復・キャッチーなポップ基盤** とし、**実験的ピークは 1作品あたり 1〜2 か所（計 10〜20% 程度）** に絞って配置する設計を初期基準とする。

### 原則 (b)：手でできないことこそ自動化し、良し悪しは「目」で判断する
- **一次出典（本人記事のみ）**：
  - 『スペクトラムの局所的なピーク押さえ＋』（2007-10-20）：手作業のノッチ EQ で追い切れない密集ピークに対し「自動化しなければ連続的にありとあらゆる場所に変化するピークを全て押さえる事は不可能。」として SuperCollider の FFT 処理を組み、最終的には「音が丸くなって非常に聞きやすい。」と**聴感で有効性を判定**。
  - 『人間の可聴域の対数的中心』（2007-07-03）：黄金比による加算合成を実装して鳴らしたうえで「黄金比を元に加算されるサイン波のサウンドが非常に退屈だった事を思い出した。」と、数式の美しさより**知覚上の面白さ**を優先。
  - 『Stereo Spread』（2008-04-06）：画一的な高音質ではなく「その音質感そのものに別な価値を見いだす」姿勢を明記。
- **映像領域への読み替え（【推測】・設計指針）**：
  - 人間の手作業では精度・反復回数・時間コストが破綻する処理——**音のオンセット／ビート／周波数帯域に対するフレーム単位の同期、手続き的な動き、数千フレームにわたる1フレーム単位のパラメータ処理**——をプログラムで自動化する。
  - 自動生成や数理モデルの結果を数値だけで「完成」とせず、**どのタイミングに見せ場を置くか、どのパターンが気持ちよい・異様・面白いかは必ず人間の「目」で審美判断する**。

### 原則 (c)：自動化の出力は、あとから編集できる形にする
- **一次出典（本人記事のみ）**：
  - 『DTM板にありがちなこと』（2008-02-13）：「SuperColliderでwslibのSimpleMIDIFileを使ってMIDIファイルを生成させるのが簡単で効果抜群で素晴らしいかないか。」「Logicと連携して効率のいい作業が是非したいところです。」また、アレンジ層とミックス層の混同を批判。
  - 『ライブマシーン作成日誌：最終章』（2008-02-17）：「適材適所があると思いました。僕の中でSCはライブツールじゃなくなってきた。NRTとかしっくりきちゃうし。」
  - 『だれかとえろいことしたいな』（2009-01-28）：Ableton Live と Logic の役割分担を実践。
- **映像領域への読み替え（【推測】・設計指針）**：
  - **AI に編集不能な完成動画（焼き込み `.mp4`）を直接生成させない**。自動化の出力は必ず、人間がタイムライン・イージングカーブ・パラメータを開いて追い込めるプロジェクト形式にする（`iketeru-production-standards` の非破壊原則とも一致）。
  - **対象フォーマット**：
    - **After Effects**：ExtendScript（`.jsx`）によるレイヤー・コンポジション・エクスプレッション・マーカー・制御ヌル構築
    - **Blender**：Python（`.py`）による Geometry Nodes・カメラ・マテリアル・ドライバー構築
    - **Premiere Pro / DaVinci Resolve**：XML / OTIO / Resolve Python による編集可能タイムライン＋BGM/SEトラック完全分離
    - **コード映像（中間・素材層）**：Remotion / p5.js / GLSL 等もシード・ソースコード・パラメータを保持して AE/Blender へ持ち込める設計とする。

### 原則 (d)：道具は自作し、数学や知覚の仕組みから新しい表現を作る
- **一次出典（本人記事のみ）**：
  - 『SuperCollider入門者を押し止める為の記事』（2007-08-08）：「何かを作る前に、使う機能の仕組みが分かってないと、どうしても気持ち悪くて使う気になれなくて、関連するHelpを読んだり、必要ならばクラスのソースを片っ端から読んだりしてまして」
  - 『SC Cellular automaton』（2007-05-03）：SuperCollider 上でセル・オートマトンを実装・検証し、「驚異的な重さと非実用性。こういうのはProce55ingでやらなきゃな。」と処理系の適材適所を判断。
  - 『サイコ・アコースティクス・イリュージョン（相手は死ぬ）』（2008-02-04）：左右 180° 位相反転により両耳聴取時のみ隠れた周期メロディが立ち上がる音響心理イリュージョンを実装し、「マスキング効果のちゃんとした勉強がしたい」と知覚研究を重視。
  - 『ライブシステム作成日誌：第何回　と、策略』（2008-04-12）／『imoutoidFXSendSystem』（2008-04-08）：独自 GUI・エフェクトバス制御システムを自作。
- **映像領域への読み替え（【推測】・設計指針）**：
  - 既製エフェクトのプリセットをそのまま貼るのではなく、**再利用可能な小さなスクリプト・エクスプレッション・シェーダを自作し、数学的構造と人間の視覚知覚の特性から独自の動きと質感を作る**。
  - **具体的な着眼点**：
    - **数学的構造**：セル・オートマトン（Life / 1D Rule 30・110）、パーリン／シンプレックスノイズ場、フーリエ／リサジュー曲線、再帰・自己相似（cyriak 的増殖）、モジュラー算術による位相ズレ。
    - **視覚知覚・錯覚の仕組み**：残像（Persistence of Vision）、1〜2フレーム交互点滅のちらつき（McLaren 的フリッカー・ストロボ効果）、仮現運動（ファイ現象）、補色残像、モアレ干渉、音と画の意図的なマイクロ先行／遅延。

## 3. 分析 DB（iketeru-eizou）の評価軸への反映案（将来実装に向けた提案）

既存の汎用プロ評価（客観アワード較正に基づく100点満点のクラフト基準）は**中立指標として独立維持**し、imoutoid 原則に基づく観点は**汎用スコアを歪めずに別の専門サブ指標・構造タグとして併設**する。

### 3.1 専門サブ指標案（汎用100点とは分離管理）
1. **`av_frame_sync_precision`（音像・フレーム同期の精度）**：音の立ち上がり・ドラム・音色変化・無音の間合いに対し、映像のカット・変形・点滅がどれだけ緻密に噛み合っているか。
2. **`pop_experiment_balance`（実験性とポップさの両立度）**：実験的な視覚表現が、キャッチーな構成・反復・感情曲線の中で「効く見せ場」として成立しているか。
3. **`procedural_reproducibility`（AE/Blender での手続き的再現・編集可能性）**：実写大予算や焼き込みAIに頼らず、AE エクスプレッション／JSX・Blender Python・GLSL 等で手続き的に再現・応用できる度合い（クラフトレシピ v2 化の優先度判定に直結）。
4. **`math_perception_craft`（数学・知覚の仕組みの活用度）**：既製プリセット依存ではなく、再帰・規則系・ノイズ場・残像・フリッカー・錯視・位相ズレ等の原理から表現を立ち上げているか。

### 3.2 構造タグ・検索軸の拡張案
- **知覚・錯覚タグ**：`残像/フリッカー`、`1フレーム点滅`、`仮現運動`、`モアレ干渉`、`補色対比`、`オーディオリアクティブ（帯域別）`
- **数学・手続きタグ**：`セル・オートマトン`、`ノイズ場`、`再帰/フラクタル増殖`、`位相ズレ/ポリリズム映像`、`グリッド変形`
- **構造設計タグ**：`ポップ基盤＋実験ピーク`、`完全ループ構造`、`自作ツール/シェーダ由来`

## 4. 将来の自動映像生成設計（AE / Blender 連携）への反映案

将来の映像生成パイプライン（`iketeru-zero-to-one-gen` / `iketeru-sound-rhythm-sheet` / レシピ v2）では、以下の 5 段階ワークフローを標準化する（実装は較正テスト完了後に別タスクとして着手）。

```mermaid
flowchart LR
  A["1. 音源解析<br/>(BPM / オンセット / 帯域別特徴量)"] --> B["2. 構成設計<br/>(ポップ基盤 + 実験ピーク1-2箇所 ※仮目安)"]
  B --> C["3. アルゴリズム・知覚設計<br/>(数学ルール / 錯覚パラメータ選定)"]
  C --> D["4. 編集可能プロジェクト自動生成<br/>(AE .jsx + Exp / Blender .py)"]
  D --> E["5. 人間の目による審美ジャッジ<br/>(プレビュー確認・手動微調整・反復)"]
  E -->|パラメータ調整| C
```

1. **音源のフレーム単位解析（自動化）**：ビート・オンセット・周波数帯域（Low/Mid/High）をフレーム単位 JSON（24/30/60fps）へ出力。
2. **ポップ基盤＋実験ピークの構成設計（人間＋AI協働）**：基本のキャッチーな視覚モチーフを定め、実験表現を解放する 1〜2 か所のピーク区間を設計上の仮目安（ポップ約80%・実験10〜20%等）を起点に設計。
3. **自作ツール・数学／知覚モジュールの組み合わせ**：再利用可能なジェネレータ群（セル・オートマトン、ノイズ場、フリッカー／残像シーケンサ、再帰クローン）を音源 JSON に接続。
4. **編集可能プロジェクトのみを出力**：AE `.jsx`（マーカー＋制御ヌル＋エクスプレッション）および Blender `.py`（Geometry Nodes＋ドライバー）を出力し、編集不能な焼き込み AI 動画の直接出力は禁止。
5. **人間の目による審美判断と追い込み**：プレビューを目で確認し、やりすぎた実験の削減や1フレーム単位のタイミング調整を手動で反復する。

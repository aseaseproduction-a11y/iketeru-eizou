# imoutoid の制作原則の映像領域への適用設計書（v1・方針整理）

> **位置づけ**：本ドキュメントは、「imoutoid が今も生きていたらどんな表現をしたか」を音楽だけでなく**映像制作・映像分析DB・将来の自動プロジェクト生成**にも一貫適用するための設計方針書である。**現段階では方針整理のみを行い、DBスキーマ変更やコード実装は行わない。**

---

## 1. 背景とユーザーの美的系譜との接続

imoutoid のブログ（126記事）から確認された制作思想は、音色・リズム・ツール設計にとどまらず、**時間軸メディア全体の構造設計論**として映像へそのまま読み替えられる。

ユーザーの「好きな映像」の系譜は以下の通りであり、imoutoid の原則と極めて高い親和性を持つ：

| ユーザーの好む映像例 | 表現上の核 | imoutoid の原則との対応 |
|---|---|---|
| **Norman McLaren『Blinkity Blank』** | フィルムへの直接彫刻による1フレーム単位の残像・ちらつき・知覚実験と、音・打撃との完全同期 | 道具の自作・知覚の仕組みの活用／手でできない単位の同期設計 |
| **cyriak の諸作品** | 再帰・フラクタル・周期的反復による数学的増殖と、思わず笑ってしまうポップさ・キャッチーさの両立 | 実験はポップの中でこそ意味がある／手続き的増殖 |
| **group_inou『EYE』** | 強いビート同期・反復フック・中毒性あるポップ構造の上に載る過激な視覚的違和感 | 実験はポップの中でこそ意味がある／音と映像のフレーム同期 |
| **モーショングラフィックス作品群** | 幾何学・グリッド・イージング曲線・タイポグラフィを精密制御する構造美 | 手でできないことこそ自動化する／編集可能なパラメータ設計 |

## 2. 4原則の映像領域への読み替え

### 原則 1：実験は、ポップの中でこそ意味がある
- **映像での定義**：グリッチ、視覚的破壊、アルゴリズム的逸脱、異常なカット密度などの実験表現は、単独の前衛アートとして垂れ流すのではなく、**明快な構成・リズム・キャッチーなフック（ポップの土台）の上に「見せ場」として 1〜2 か所配置する**ことで初めて視聴者の記憶と感情を揺さぶる。
- **反パターン（避けるべき設計）**：全編が脈絡なくグリッチ・ノイズ・AI生成クリップの羅列になり、構成の軸や気持ちよい反復が失われている状態。
- **設計指針**：
  - 楽曲・構成の全体設計において「安定・反復・キャッチー（80%）」と「構造的裏切り・実験ピーク（1〜2か所、計10〜20%）」のコントラストを明示的に設計する。

### 原則 2：手でできないことこそ自動化する
- **映像での定義**：人間の手作業では精度・反復回数・時間コストが破綻する領域——**音のオンセット／ビート／周波数帯域に対するフレーム単位の同期、手続き的な動き、数千フレームにわたる1フレーム単位のパラメータ処理**——こそをプログラムで自動化する。
- **人間と自動化の役割分担**：
  - **自動化が担うもの**：音解析（BPM・オンセット・帯域別エンベロープ）、フレーム単位のキーフレーム生成、再帰・ルールベースの配置、反復バリエーション展開。
  - **人間（目）が担うもの**：どのタイミングに見せ場を置くか、どのパターンが「気持ちいい／面白い／異様」かという**審美判断（良し悪しの最終ジャッジ）**。

### 原則 3：自動化の出力は、編集できる形にする
- **映像での定義**：生成AIに完成済みの焼き込み動画（`.mp4`）を直接作らせない。自動化の出力は必ず**人間がタイムライン・カーブ・パラメータを開いて手で追い込めるプロジェクト形式**にする。
- **対象フォーマット（`iketeru-production-standards` の非破壊原則と完全一致）**：
  - **After Effects**：ExtendScript（`.jsx`）によるレイヤー・コンポジション・エクスプレッション・マーカー・調整レイヤー構築
  - **Blender**：Python（`.py`）によるプロシージャルジオメトリ（Geometry Nodes）、カメラ、マテリアル、ドライバー構築
  - **Premiere Pro / DaVinci Resolve**：XML / OTIO / Resolve Python による編集可能タイムライン＋BGM/SEトラック完全分離
  - **コード映像（中間・素材生成）**：Remotion / p5.js / GLSL 等もパラメータ・シード・ソースコードが完全に再現・改変可能な形で管理し、AE/Blender へ取り込める設計とする。

### 原則 4：道具は自作し、数学や知覚の仕組みから新しい表現を作る
- **映像での定義**：既製エフェクトのプリセット（量産的なグリッチ／トランジション）をそのまま貼るのではなく、**小さな専用スクリプト・エクスプレッション・シェーダを自作し、数学的構造や人間の視覚知覚の特性から独自の動きと質感を生み出す**。
- **具体的な着眼点**：
  - **数学的構造**：セル・オートマトン（Life / 1D Rule 30・110）、パーリン／シンプレックスノイズ場、フーリエ展開・リサジュー図形、再帰・自己相似（cyriak 的増殖）、モジュラー算術による位相ズレ。
  - **知覚・錯覚の仕組み**：残像（Persistence of Vision）、1〜2フレーム交互点滅によるちらつき（McLaren 的フリッカー・ストロボ効果）、仮現運動（ファイ現象）、補色残像、モアレ干渉、マイクロ・タイミングの意図的な先行／遅延（音の1フレーム前に画を動かす等）。

## 3. 分析 DB（iketeru-eizou）の評価軸への反映案（将来実装に向けた提案）

既存の汎用プロ評価（100点満点のクラフト基準・国際アワード較正）は**中立な客観指標として独立維持**し、imoutoid 原則に基づく観点は**汎用スコアを歪めずに別の専門サブ評価・構造タグとして併設**する設計を推奨する。

### 3.1 専門サブ指標（各 0〜5 点または 3 段階、汎用100点とは分離管理）
1. **`av_frame_sync_precision`（音像・フレーム同期の精度）**
   - 音の立ち上がり・ドラム・シンセ変化・無音の間合いに対し、映像のカット・変形・点滅がどれだけ緻密に噛み合っているか（単なるBPM合わせではなく、微細な音色変化への追従・意図的なズレを含む）。
2. **`pop_experiment_balance`（実験性とポップさの両立度）**
   - 難解・実験的な視覚表現が、キャッチーな構成・反復・ユーモア・感情曲線の中で「効く見せ場」として成立しているか（実験に偏りすぎて孤立していないか／ポップに偏りすぎて定型化していないか）。
3. **`procedural_reproducibility`（AE/Blender での手続き的再現・編集可能性）**
   - その映像表現の核となる動き・構造を、実写大予算や焼き込みAIではなく **AE エクスプレッション／JSX・Blender Python・GLSL 等で手続き的に再現・応用できる度合い**（クラフトレシピ v2 化の優先度判定に直結）。
4. **`math_perception_craft`（数学・知覚の仕組みの活用度）**
   - 既製プリセット依存ではなく、再帰・規則系・ノイズ場・残像・フリッカー・錯視・位相ズレ等の原理から表現を立ち上げているか。

### 3.2 構造タグ・検索軸の拡張案
- **知覚・錯覚タグ**：`残像/フリッカー`、`1フレーム点滅`、`仮現運動`、`モアレ干渉`、`補色対比`、`オーディオリアクティブ（帯域別）`
- **数学・手続きタグ**：`セル・オートマトン`、`ノイズ場`、`再帰/フラクタル増殖`、`位相ズレ/ポリリズム映像`、`グリッド変形`
- **構造設計タグ**：`ポップ基盤＋実験ピーク`、`完全ループ構造`、`自作ツール/シェーダ由来`

これにより、分析 DB から「汎用ランクが高い作品」だけでなく、**「imoutoid 的な構造美（ポップ×実験×音像同期×手続き的再現性）を持つリファレンス」をピンポイントで検索・レシピ抽出**できるようになる。

## 4. 将来の自動映像生成設計（AE / Blender 連携）への反映案

将来の映像生成パイプライン（`iketeru-zero-to-one-gen` / `iketeru-sound-rhythm-sheet` / レシピ v2）では、以下の 5 段階ワークフローを標準化する。

```mermaid
flowchart LR
  A["1. 音源解析<br/>(BPM / オンセット / 帯域別特徴量)"] --> B["2. 構成設計<br/>(ポップ土台80% + 実験ピーク1-2箇所)"]
  B --> C["3. アルゴリズム・知覚設計<br/>(数学ルール / 錯覚パラメータ選定)"]
  C --> D["4. 編集可能プロジェクト自動生成<br/>(AE .jsx + Exp / Blender .py)"]
  D --> E["5. 人間の目による審美ジャッジ<br/>(プレビュー確認・手動微調整・反復)"]
  E -->|パラメータ調整| C
```

1. **音源のフレーム単位解析（自動化）**：楽曲のビート・サブビート・オンセット（ドラム／アタック）・周波数帯域（Low/Mid/High）をフレーム単位の JSON（24/30/60fps）へ書き出す。
2. **ポップ土台＋実験ピークの構成設計（人間＋AI協働）**：曲のセクション（Intro / Verse / Chorus / Bridge / Drop）に沿って、基本のキャッチーな視覚モチーフを定め、**実験的表現を解放する 1〜2 か所のピーク区間**を明示的に指定する。
3. **自作ツール・数学／知覚モジュールの組み合わせ**：再利用可能な小さなジェネレータ群（例：1D/2D セル・オートマトン生成、ノイズ場ベクトル、フレーム単位フリッカー／残像シーケンサ、再帰クローン配置）を楽曲 JSON と接続する。
4. **編集可能プロジェクトのみを出力**：
   - AE 向け：マーカー付きコンポジション、オーディオ特徴量キーフレームを格納した制御ヌル、制御スライダー付きエクスプレッションを生成する `.jsx`。
   - Blender 向け：フレーム別オーディオ特徴量をドライバー／Geometry Nodes 属性へ流し込み、非破壊で再調整可能な `.py`。
   - **禁止**：編集不能な焼き込み AI 動画の直接出力。
5. **人間の目による審美判断と追い込み**：自動生成したプロジェクトをプレビューし、「やりすぎた実験を削る」「1フレームだけタイミングを前に詰める」「配色や間合いを手で調整する」工程を必須ループとして組み込む。

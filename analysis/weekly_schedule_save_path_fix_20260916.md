# 週次スケジュールの保存経路修正（2026-09-16）

## 原因

保存済みの週次タスクは、2026-09-13 22:01:05 UTCに実行済みだったが、新規追加・既存更新の実行ログが作られていなかった。旧プレイブックは隔離された定期実行に対してローカルの`node scripts/apply_weekly_collection_candidates.mjs`を実行するよう指示していた。この実行環境にはプロジェクトのローカルソース・DB接続は存在しないため、候補の保存まで到達できなかった。

## 修正

サイトには既に、定期実行の認証を確認したうえで候補を保存する以下のエンドポイントがある。

| 用途 | エンドポイント | 処理 |
|---|---|---|
| 有効収集元・差分起点取得 | `GET /api/scheduled/daily-video-collection/sources` | 有効な収集元台帳と`lastCheckedAt`を返す |
| 候補保存 | `POST /api/scheduled/daily-video-collection` | 新規追加、既存の安全な更新、実行ログ記録、確認時刻更新を行う |

更新済みプレイブックでは、定期実行に自動注入される短命の認証コンテキストを使い、上記エンドポイントを`curl`で呼ぶ。認証値自体は保存・報告しない。保存応答の`inserted`、`updated`、`skipped`、`runId`だけを実績報告に用いる。

スケジュールは自己完結型プレイブック付きの新規実行モードへ切り替えた。これにより、隔離された各実行でもサイトのDB保存処理へ到達できる。
